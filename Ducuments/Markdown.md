# SoulArchive.AI v1.1 仕様（Markdown出力）

## 1. 先頭タイトル
- 生成する Markdown の **1行目**に、ページの `head > title` の中身を以下の形式で出力する。
  - `# {pageTitle}`
- タイトル行の次に **空行を1行**入れる。
- その次の行から会話本文を開始する。

---

## 2. 改行処理ルール（本文）
### 2.1 基本定義
- **段落**：空行（= 連続した改行）によって区切られる。
- **単一改行**：空行ではない改行（次行が空行ではない改行）。

### 2.2 変換ルール
- 本文中の **単一改行**は、行末に **半角スペース2つ**を付与して改行する（Markdown の hard line break）。
  - 例：`行A␠␠\n行B`
- ただし、次行が空行の場合（= 段落区切りの場合）は、行末に半角スペース2つを付与しない。
  - 例：`行A\n\n行B` はそのまま保持

### 2.3 例
入力（抽出テキスト）:
あいうえおかきくけこさしすせそ
たちつてと

なにぬねの

出力（Markdown）:
あいうえおかきくけこさしすせそ␠␠
たちつてと

なにぬねの

### 2.4 除外（必須）
- 次のブロック内は **改行処理を行わない**（内容を一切変更しない）。
  - コードブロック（fenced code block）：` ``` ` で囲まれた範囲（開始〜終了まで）

---

## 3. リストの入れ子（スペース4つ方式）
### 3.1 対象
- 箇条書き（ul：`-` / `*`）および番号リスト（ol：`1.` など）
- リストの入れ子を検出し、Markdownとして破綻しないインデントに正規化する。

### 3.2 ルール
- 入れ子の深さが 1 増えるごとに、先頭に **スペース4つ**を追加する。
- 入れ子は `ul` / `ol` の組み合わせを問わず、深さで一律に処理する。
  - 例：`ul > ol > li` の場合、ol側の `1.` の前にスペース4つを付与して表現する。

### 3.3 除外
- コードブロック内は対象外（変換しない）。

---

## 4. 話者行の形式（ユーザー名・キャラ名）
- 話者名（ユーザー名・キャラ名）の行は、必ず以下の形式にする。
  - `{speakerName}:` の **直後で必ず改行**する（同一行に本文を続けない）
- 話者行の後に本文を置く。本文が空の場合でも、話者行は保持する。

例:
カイエ:
本文...

ソラ:
本文...

---

## 5. URL付きリンク（Markdown化）
### 5.1 変換ルール
- URL とリンクテキストが取得できる場合は、Markdownリンク形式に変換する。
  - `[リンクテキスト](URL)`
- リンクテキストが取得できない場合は、URLをそのまま出力する（URLのみ）。
- 既に Markdown リンク形式になっている場合は可能な限り保持する（重複変換しない）。

### 5.2 除外
- コードブロック内は対象外（変換しない）。

---

## 6. 末尾メタ表記
- 会話本文の末尾に、本文と明確に分離したメタ情報ブロックを付与する。
- 形式は以下で固定する（改行位置も固定）。

===
Note:
- URL: {pageUrl}

### 6.1 任意（入れる場合）
- 必要に応じて、以下をNote内に追加してもよい（順序は固定推奨）。
  - `- Title: {pageTitle}`
  - `- Service: {serviceName}`

※ SoulArchive.AI の哲学に合わせ、メタは最小限に留め、本文（会話）を汚さない。
